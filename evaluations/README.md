# Native behavioral evaluation

Keep structural validation separate from native execution. Case input files contain only requests and raw artifacts. Expected outcomes live in rubric.json outside each session workspace. Do not give that file, prior session conclusions, or evidence reports to the evaluating session.

Run `node evaluations/run-native.mjs --tool codex --output /absolute/new-evidence-directory` or select `claude`; add `--case case-01` for a focused run or a comma-separated list such as `--case case-06,case-07,case-08,case-09`. Use an authenticated account and clients supporting custom roles/skills. For Codex, the runner prefers the desktop-provided `CODEX_CLI_PATH` when present, falling back to `codex` on PATH. Use `--client /absolute/native-client` to select a client explicitly; evidence records the selection method and actual client version. An older global CLI can reject a model available through the newer desktop client. Each case gets a fresh exported profile, project context, a frozen installation of the repository-pinned tooling dependencies, and pinned CLI-generated OpenSpec integrations in an isolated disposable workspace. The runner uses native permissions and a 120-second per-session bound. Use `--timeout-ms 300000` for multi-role runs that need more time; timeouts remain explicit incomplete outcomes. Native model events are captured without inspecting environment variables or credentials. Claude print sessions explicitly allow the fixture Node checks and pinned OpenSpec commands through `--allowedTools`; other commands retain native approval rules. These session flags do not modify exported adapters or global settings. The runner operates in disposable fixtures, never production apps, deployment, external messages, global configuration writes, or approval bypasses. Case-09 explicitly removes independent delegation capability. The runner does not score itself.

Run harmless discovery/delegation with `--case smoke`: the native coordinator must find the three custom skills and execute separate core-reviewer/core-qa roles on raw requirements/artifacts. Check role identity and independence in the transcript; reading role files alone is not delegation evidence. Requested settings come from the manifest, actual runtime models from observable native events. If unavailable, explicitly record the resolution limitation; do not infer execution from configuration.

Review the raw records against rubric.json in a separate coordinator execution. Record client version, each requested/observed route, artifacts, commands/outcomes, review/QA identity, runtime models or resolution limits, and acceptance boundaries in evidence/. Redact credentials and disposable absolute paths before committing evidence. Retain useful raw command/event excerpts, not provider telemetry or private account details.

For planning cases, verify artifacts exist and implementation stays unchanged. For direct cases, inspect changed files and run observable checks. For QA, verify the omitted failure is actually exercised. For correction cases, count cycles rather than trusting a success statement. Native access failures leave the gate incomplete; successful file parsing is not a substitute. Correct guidance only for demonstrated behavioral failures, then rerun affected cases.

The full core change remains unaccepted until both native profiles, independent review/QA, and owner acceptance pass. No fixture or evaluation deploys the result.
