# deliver-change

Read [workflow](../../guidance/workflow.md), then announce the route. Load [engineering](../../guidance/engineering.md) for discovery and implementation, and [verification](../../guidance/verification.md) for delivery gates. Read configured project documents.

For new behavior, use the installed OpenSpec proposal integration and end the planning turn with artifacts for owner acceptance. A new owner request accepting those artifacts is required before apply. For an active accepted change, use the installed apply integration. For unclear reports investigate first; for understood local fixes or text corrections work directly with proportionate checks.

Coordinate bounded roles according to [implementer](../../roles/implementer.md), [reviewer](../../roles/reviewer.md), and [QA](../../roles/qa.md). Keep reviewer inputs free of implementation conclusions. Track at most two unsuccessful correction cycles per gate; escalate or report the blocker. Report evidence and missing capabilities truthfully, then present the result for owner acceptance.
