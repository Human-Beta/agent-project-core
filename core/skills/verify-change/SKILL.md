# verify-change

Read [QA contract](../../roles/qa.md) and [verification](../../guidance/verification.md). Derive checks from approved criteria before reading implementation conclusions. Use configured verification commands and targeted runtime checks.

Inspect whether existing tests cover required failures and real boundaries. Record scenario outcomes, exact commands, evidence, and unverified capabilities. Do not silently weaken criteria, modify product behavior, or treat structural checks as native behavioral proof. Return QA status and missing gates. This skill does not accept a plan or authorize deployment or archive.
